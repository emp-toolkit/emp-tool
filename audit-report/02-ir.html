Boolean IR, contexts & sessions

The middle layer of the stack: a flat, protocol-neutral boolean-circuit IR with a native .empbc wire format, the C++20 BooleanContext concept and its reusable realizations, the generic WireValue structural-value contract, and the session layer that owns the I/O boundary. The central principle is one circuit source, many semantics: a circuit is written once over a BooleanContext and evaluated under any context — plaintext eval, gate counting, fingerprinting, IR recording, or a cryptographic backend — with the gate stream guaranteed identical across all of them. I/O (input/reveal) lives outside the gate concept, at the session.

A.1 · The IR data model

ir/program.h

The canonical stored/replay representation has one gate encoding and is protocol-neutral — the IR knows nothing about parties, owners, argument boundaries, labels, or MACs (those live in the layers that produce and consume it). Contexts may also evaluate directly or record through RecordCtx; they do not have to materialize execution as a BooleanProgram unless they are loading, saving, compiling, or replaying this IR. Opcodes (program.h:25):

enum class Op : uint8_t { And=0, Xor=1, Not=2, Const0=3, Const1=4 };  // == on-disk .empbc codes

Public constants are first-class Const0/Const1 gates with no operands, so each backend realizes a known 0/1 wire however its protocol prescribes. The IR records all Boolean operations explicitly; backend cost models are deliberately outside the data model. A Gate is {in0,in1,out,op} with in1 normalized to 0 for Not/Const* (program.h:30-38). A BooleanProgram (program.h:54-65):

uint32_t  num_wires;      // total wire ids; valid ids [0, num_wires)
uint32_t  num_inputs;     // input wires [0, num_inputs)
WireReuse wire_reuse;     // None = dense/SSA (the default contract)
std::vector<Gate>     gates;     // topological (emission) order
std::vector<uint32_t> outputs;   // wire ids of the return value (may name inputs = passthrough)

Inputs are wires [0,num_inputs) in every mode. Under the default WireReuse::None the program is dense/SSA-like: every other wire is produced by exactly one gate in topological order; wire id == position, no holes (num_wires == num_inputs + num_gates). Since 67642c2 that dense contract is one of three wire-id modes, not the sole contract — see the next section.

A.1a · WireReuse & the compaction transform

ir/program.h ir/transform.h

enum class WireReuse : uint8_t { None=0, Linear=1, Full=2 } (program.h:52) is carried on the program as wire_reuse = WireReuse::None by default (program.h:57). The design comment (program.h:40-51) draws the dividing line at stored per-gate state: a multi-pass consumer recomputes linear (Xor/Not/Const) gates every pass, so their output ids are always safe to recycle, but an And output may hold stored state across passes (e.g. a fresh authenticated mask in a garbling backend).

  • None — the dense/SSA contract above, unchanged; the only mode the analysis passes and the scheduler accept (§A.4/§A.5).
  • Linear — ids of dead linear-gate outputs are recycled; And outputs are never recycled. Safe for every consumer, including a multi-pass garbling backend.
  • Full — any id may be reused once dead, And outputs included. Maximal compaction; correct only for single-pass / recompute execution.

The symmetric transform pair lives in ir/transform.h: make_compact(dense, target) (transform.h:39-86) is a liveness-driven wire-id compaction — it runs liveness_pass on the dense input (transform.h:45, never on a reuse program), pins inputs/outputs (and, for Linear, every And output, transform.h:51-52), and assigns ids via a LIFO freelist that recycles a slot only after the gate that last reads it (transform.h:73-80). It returns a CompactResult{prog, nid[]} (transform.h:29-32; nid[dense_id] = compact_id). Preconditions are unconditional fatal error()s, not asserts: target == WireReuse::None and a non-dense input are both rejected (transform.h:40-43). Compaction never changes the gate sequence or the function — only the wire ids. uncompact(src) (transform.h:92-113) is the inverse: one forward walk relabels any reuse level back to dense (no liveness needed), validating on entry and exit. The frontend exposes this as compile_linear<ArgVs...>(body) (circuit_fn.h:248-249, over the shared compile_at_ at circuit_fn.h:231-243): compile dense first — so every existing diagnostic fires on the dense path — then compact; the documented form for a unit composed on a multi-pass backend (docs/composition.md).

Compaction is execute-compare + digest tested

test_transform.cpp:69-85 checks, over random dense circuits, that Linear/Full compaction and uncompact(Linear) all compute identical outputs to the dense original and that Full ≤ Linear < dense in wire count; test_transform.cpp:98-106 forks-and-checks both fatal preconditions; test_transform.cpp:108-121 repeats the execute-compare on the real sha256_256 builtin.

A.2 · Validation invariants

ir/validate.h

validate_program (validate.h:41-132) is the single structural validation path — run at IR construction / file load / artifact validation boundaries, not during trusted replay. It calls the stack-wide fatal error() path on the first violation; rejection is always-on in Release but not catchable in-process. Since 67642c2 it is a two-mode function: after the shared num_inputs ≤ num_wires check (validate.h:43-44) it branches on p.wire_reuse != WireReuse::None (validate.h:50). The dense (None) branch enforces:

  1. num_inputs ≤ num_wires (validate.h:43-44, shared by both branches).
  2. Density: num_gates == num_wires − num_inputs — every non-input wire produced exactly once, no holes (validate.h:95-98). This is what lets num_wires size the scratch buffer exactly.
  3. Read-before-define / in-range reads in topological order (validate.h:107-116).
  4. Canonical operands, shared helper validate_gate_operands (validate.h:20-39): Not has in1==0 (validate.h:26-27); Const* have in0==in1==0 (validate.h:29-31).
  5. Output validity: each gate's out is in range, is not an input wire, and is defined exactly once (validate.h:117-124).
  6. Every output wire is in range and defined (validate.h:127-131).

The reuse branch (validate.h:50-93) deliberately drops the dense-count and single-definition checks — a reuse program rewrites the same wire id on purpose — and keeps in-range reads, written-before-read (validate.h:73-76), out ≥ num_inputs / out < num_wires (validate.h:82-85), canonical operands, and written outputs (validate.h:88-91). It proves the program is executable, not that it is behaviorally equivalent to any dense source: Linear and Full are structurally identical here — the And-pinning distinction is a producer property this check cannot verify (comment, validate.h:51-57). Liveness-safety of a given reuse is the producer's contract (ir/transform.h), covered by execute-compare + digest tests, not by the validator.

Hardened against malformed headers — both branches

Dense branch: the defined_non_input bitmap is sized to num_wires − num_inputs (not num_wires), so a malformed file declaring a huge num_inputs cannot force a giant allocation during validation (validate.h:100-104), and the dense-count check at validate.h:95-98 runs before that allocation. Reuse branch, same discipline: an always-on bound num_wires ≤ num_inputs + num_gates (a reuse program never has more distinct ids than its dense equivalent) is rejected before any allocation (validate.h:62-63), and the written[] scratch tracks only non-input slots (validate.h:64-68). Each dense invariant is independently exercised in test_boolean_program.cpp:76-86, the huge-sparse-header guard at test_boolean_program.cpp:140-149, and the two reuse-path hostile headers (huge num_wires with zero inputs rejected up front; num_inputs == num_wires == 0xFFFFFFFF with no gates must load cheaply as a no-op, zero-sized written[]) at test_boolean_program.cpp:151-180. Reuse validation and its negative cases: test_boolean_program.cpp:183-219.

validate_program is fatal even in Release

The IR validator is unconditional — it is not guarded by NDEBUG — but it follows the same fail-fast model as the rest of emp-tool: error() prints the call site and terminates with std::_Exit(1). A consumer that passes an externally supplied program through validate_program (the .empbc loader does) gets process-level rejection in both Debug and Release, never silent corruption. Tests for malformed programs must assert child-process death, not catch an exception.

A.3 · The .empbc serialization format

ir/empbc.h

The one native persisted format. Layout (empbc.h:17-30): magic EMPB, version u16 (currently 1), index_width u8 (2 or 4), flags u8, then num_wires/num_inputs/num_outputs/num_gates as u32, then gate records, then outputs. Since 67642c2 the flags byte is no longer purely reserved-must-be-zero: bits 0-1 carry the WireReuse mode (0=None, 1=Linear, 2=Full; empbc.h:21-22, written at empbc.h:98); value 3 and bits 2-7 remain reserved. Indices are stored 16- or 32-bit on disk (the writer auto-selects u16 when num_wires ≤ 0xFFFF, empbc.h:90) but always decode into a uint32_t BooleanProgram — the compact width is a disk detail, never a second in-memory IR.

Hostile-input-safe parser

A bounds-checked Reader (empbc.h:60-76) does fixed little-endian field reads (never a struct overlay / reinterpret_cast, so it is endian- and layout-independent). load_empbc (empbc.h:117-165) checks magic / version / index_width, rejects any unknown flags bits (flags & ~0x3u) and the reserved wire_reuse value 3 (empbc.h:127-129), performs an overflow-checked exact size equation in 64-bit (empbc.h:141-145, rejecting both truncation and trailing bytes), range-checks each op code (empbc.h:154), and runs a final validate_program (empbc.h:163). The flags check is fail-closed in both directions: a pre-67642c2 reader rejected any nonzero flags byte, so an old binary handed a Linear/Full-flagged file errors out rather than silently misinterpreting it. The writer save_empbc validates first (empbc.h:89) — for both dense and reuse programs — so a malformed program can't be silently truncated by the u16 writer. The malformed/truncated/trailing/bad-magic/bad-op cases are exercised in test_boolean_program.cpp:125-149; the reuse-mode roundtrip (flags byte preserves Linear/Full, bad flags rejected) at test_boolean_program.cpp:183-219; and a compact-program roundtrip load_empbc(save_empbc(lin)) that preserves wire_reuse == Linear and execution behavior at test_transform.cpp:87-96.

Minor forward-compat ambiguity

The header flags byte is value-checked on read (unknown bits and the reserved mode value 3 are fatal, empbc.h:127-129), but per-gate reserved padding bytes are read without value-checking (empbc.h:156-157) — a nonzero gate-record reserved byte is silently accepted. load_empbc_file reads the whole file into memory via ftell before the exact-size check (empbc.h:173-185).

A.4 · Analysis passes

ir/passes.h

Protocol-neutral pure-function analyses over a materialized BooleanProgram, each computed once and optionally cached on the frontend Circuit. Per-wire scratch (first-def / last-use / level) uses signed vectors with a −1 "none" sentinel — local analysis state, never serialized (passes.h:11-15).

  • count_pass (passes.h:49-65) → AND/XOR/NOT/CONST tallies plus wire/gate/input/output counts (the stored-program analogue of CountCtx). The one pass with no per-wire array — it tallies only, so it accepts any WireReuse mode.
  • liveness_pass (passes.h:72-86) → per-wire last_use + first_def.
  • schedule_pass (passes.h:93-119) → AND-depth of each wire (Const=0; Not inherits its input level; Xor inherits the max input level; And = 1 + max(level(in0),level(in1)), passes.h:101-108) and AND gates grouped by level — metadata the scheduled replay path can use for bulk and_many batching.
  • layout_pass (passes.h:133-164) → frees[gi] (slots recyclable after gate gi, with output wires excluded as roots) plus an output-rooted dead-code- elimination sizing (backward reachability counting reachable_wire / reachable_and, passes.h:146-162). Note this reports DCE sizes but does not rewrite the program — execution still walks all gates.
Dense-only passes now refuse a reuse program (67642c2)

require_dense(p, who) (passes.h:31-33) is a fatal, always-on error() if p.wire_reuse != WireReuse::None, called at the top of liveness_pass (passes.h:73), schedule_pass (passes.h:94), and layout_pass (passes.h:134). Rationale (passes.h:27-30): these passes index per-wire arrays last-writer-wins; on a reused id they would silently collapse distinct lifetimes and misorder replay — the guard converts that correctness bug into a loud rejection. Exercised (fork-based dies()) by feeding make_compact(sample(), Linear) to all three passes, test_passes.cpp:191-195. Compaction itself computes liveness on its dense input, never its reuse output (transform.h:45).

A.5 · Scheduled bulk replay

ir/schedule.h

Round-sensitive bulk replay for protocols whose latency depends on minimizing AND-depth: bucket all gates by their output wire's AND-depth, then batch each level's ready AND gates into one and_many call and run that same level's non-AND gates in emission order (schedule.h:78-100). Correctness is identical to the scalar execute_program; only batching changes. A ScheduledPlan (schedule.h:28-39) caches gate indices per AND-depth plus the program's identity (num_inputs/num_wires/num_gates/digest) for staleness checking. Per level: collect the level's AND operands/outputs → one and_many → run the level's Const/Xor/Not gates in emission order. Since 67642c2 the first check in scheduled_execute_program is circuit::require_dense(p, ...) (schedule.h:63) — an always-on fatal rejection of a WireReuse::Linear/Full program handed to the scheduler.

Schedule digest guard is debug-only

Three staleness guards: the input count and the plan dimensions (num_inputs/num_wires/num_gates) are always-on error() checks (schedule.h:64-68), but the strong "same shape, different gate stream" guard plan.digest == digest_program(p) is wrapped in #ifndef NDEBUG (schedule.h:69-72). In a Release build, a ScheduledPlan whose dimensions match a different but same-shaped program would silently misexecute. Whether reachable depends on the backend's plan-caching discipline. (Scheduled == scalar replay is cross-checked on real AES/SHA/SHA3 circuits, test_builtin_circuits.cpp:48-52.)

A.6 · The single gate-walk & execution

ir/visit.h ir/execute.h

for_each_gate(p, visitor) (visit.h) is one of several defaultless op-switches (the others in schedule.h / passes.h / digest.h) — adding a new Op is a -Werror=switch compile error at every site, never a silent fallthrough. The one sanctioned default: lives in validate_gate_operands (validate.h:33-37): there the op may be a raw byte from a loaded file, so an out-of-range value is a runtime condition (fatal error()), not a missed enum case (visit.h:5-10). Execution has two layers:

  • Low level circuit::execute_program<Wire,Dispatcher> (execute.h:44-70) — seed input slots, walk once via for_each_gate through a Bridge that maps wire ids to value slots, copy outputs out; generic over a wire slot type and an in-place Dispatcher. Validates input/output counts (fatal error() on mismatch, execute.h:50-53), sizes scratch to num_wires.
  • High level value-return bridge execute_program(ctx, program, inputs[, ws]) (execute.h:102-122) — the way stored .empbc builtins and compiled frontend circuits run through any BooleanContext, via a CtxReplayAdapter (execute.h:89-97) that turns the context's value-return gates into the in-place form. A ProgramWorkspace<Wire> (execute.h:79-86) holds reusable buffers (scratch, output, AND-batch buffers) — must be caller-owned or thread_local, never one process-wide mutable instance.
Trusts prior validation

execute_program validates input/output counts but re-checks nothing about the program's internal validity — it trusts validate_program ran at load/record time (the comment in validate.h:4-8 states this contract: validation runs at construction/load, "never inside the execution hot loop"). An externally-supplied, unvalidated program reaching execute_program would read out-of-range slots; the documented contract is that validation happens at the boundary, not here.

A.7 · Artifacts, assets & builtins

ir/artifact.h ir/assets.{h,cpp} ir/builtins.{h,cpp}

A CircuitArtifact is a BooleanProgram + a CircuitSignature (arg_widths + return_width — the argument boundaries the flat IR omits, artifact.h:21-33). validate_artifact (artifact.h:37-46) runs validate_program and checks sum(arg_widths) == num_inputs and return_width == outputs.size() in 64-bit. Big circuits (AES-128, SHA-256, SHA3-256, and the per-width float ops) ship as <name>.empbc under ir/files/ (63 committed assets) and are loaded/validated/cached once behind a mutex-guarded std::map (builtins.cpp:15-30, and float_circuit at builtins.cpp:32-47) then replayed through any context. The aes128 builtin has 256 inputs (pt ‖ key) and 128 outputs (test_builtin_circuits.cpp:63-64).

Asset loading: structurally safe, not authenticated — and EMP_CIRCUIT_DIR is honored first

Asset resolution searches, in order (assets.cpp:35-45): EMP_CIRCUIT_DIR (env var) → build-tree dir → install-tree dir. In a deployment where the environment is attacker-influenced, this allows redirecting builtin-circuit loads to an attacker-chosen directory. The .empbc loader's hostile-input safety is the only mitigation: a substituted file is still structurally validated, but it could be a different valid circuit (e.g. a weakened AES). There is no hash/signature/MAC on .empbc. Whether this matters depends on the trust model.

IR-replay path proven faithful

Each shipped builtin, replayed through ClearCtx (scalar and scheduled), is compared bit-for-bit against the context-native crypto kernel on random input (test_builtin_circuits.cpp:26-91): the test cross-checks aes128, sha256_256, and sha3_256_256 against the in-circuit kernels and asserts scalar-replay == kernel and scheduled-replay == scalar.

B.1 · The BooleanContext concept

ir/context/concept.h

The contract (concept.h):

template <class Ctx>
concept BooleanContext =
    std::semiregular<typename Ctx::Wire> &&
    requires(Ctx& c, typename Ctx::Wire a, typename Ctx::Wire b, bool v) {
        { c.public_bit(v) } -> std::same_as<typename Ctx::Wire>;
        { c.and_gate(a, b) } -> std::same_as<typename Ctx::Wire>;
        { c.xor_gate(a, b) } -> std::same_as<typename Ctx::Wire>;
        { c.not_gate(a) }    -> std::same_as<typename Ctx::Wire>;
    };
  • Ctx::Wire must be std::semiregular — copyable, because "fan-out needs copies" (concept.h:17-18). A wire is a cheap handle; the context holds the real state.
  • Gates return by value, not in-place mutation — static, inlineable dispatch (concept.h:4-7).
  • The concept does NOT require input/reveal/output. There is no private_input or reveal at the gate level — those live in the session layer. public_bit is the only "input" and it is for public constants.
  • No NOR/OR/MUX primitive — OR, equality, select are built in the value layer on the four primitives (e.g. a|b = a^b^(a&b)).

A refinement BulkBooleanContext adds and_many(o, a, b, n) to evaluate a whole AND layer at once (concept.h:32-40); the scheduler needs only this, and the win materializes only when a backend overrides the default scalar loop.

B.2 · The context taxonomy

Four reusable in-tree realizations, each a tiny struct static_assert-ed to satisfy BooleanContext, each giving a different interpretation of the same kernel — plus an opt-in fifth, ComposeCtx (§B.2a, added by 67642c2 and deliberately not pulled in by the ir/context/context.h umbrella) — plus the block-valued garbling backends downstream protocol repos supply.

ClearCtx (clear.h:16-26): not_gate XORs only the low bit (a^1); the default and_many is a scalar loop. CountCtx (count.h:16-25) dedups Const0/Const1 with c0_seen/c1_seen so its tallies match a recorded program. RecordCtx (record.h:20-58) is the linchpin of "record once, replay anywhere": all inputs must be reserved before any gate — external_input(n) reserves [0,num_inputs), and a late external_input after the first gate hard-error()s (record.h:28-38; the inputs_closed flag is flipped by alloc_() at record.h:27, and the check is always-on, not debug-only). finish(outputs) runs validate_program (record.h:51-57), so a recorder cannot hand out malformed IR. DigestCtx (digest.h:20-51) mirrors RecordCtx's wire numbering and const-dedup precisely so the two digests agree.

B.2a · ComposeCtx — recording a hierarchical composition

ir/context/compose.h circuits/frontend/compose.h

Added by 67642c2. ComposeCtx satisfies BooleanContext (static_assert, compose.h:103) with Wire = uint32_t, but unlike the four contexts above it records a two-level, hierarchical circuit: ordinary "glue" gates interleaved with opaque unit calls, in emission order, as a ComposePlan{num_inputs, num_wires, events[], instances[], outputs[]} (compose.h:44-50). Each ComposeInstance (compose.h:28-32) is a reference — a const BooleanProgram*, not a copy — plus its wiring (in_ids/out_ids); call_unit(unit, in, n) (compose.h:84-93) records a call in O(width), never O(unit gate count). Both headers are opt-in: ir/context/context.h still lists only concept/clear/count/digest/record, and circuits/frontend/frontend.h includes only circuit_fn.h + rec.h.

  • RecordCtx discipline shared. external_input(n) must run before any gate or call (inputs_closed flips on the first alloc_()/call_unit, compose.h:59-69, compose.h:85; always-on error()), and the two constants are deduped via cached c0/c1 ids (compose.h:56, compose.h:72-76).
  • No new call verb. The frontend's run(ctx, circuit, args...) is now opaque-or-inline purely by the type of ctx: if constexpr (std::same_as<remove_cvref_t<Ctx>, ComposeCtx>) it records one opaque instance via call_unit (circuit_fn.h:281-284); on every other context it takes the previously documented inline path (execute_program + ProgramWorkspace). The EMP_CONTEXT_CHECKS argument-context check that used to run unconditionally before replay now runs only inside the inline (else) branch (circuit_fn.h:286-290) — functionally unchanged for existing callers.
  • Recording a composition. compose<ArgVs...>(body) (frontend/compose.h:37-50) records an explicit-ctx body over a fresh ComposeCtx (one external-input window per ArgV via make_compose_arg, frontend/compose.h:25-31) and returns the ComposePlan. ArgVs must satisfy RecordValue — the same constraint compile() imposes.
  • Fallback / oracle. flatten_compose(plan) (compose.h:111-146) materializes the full dense BooleanProgram by inlining every instance's referenced unit (O(total flattened gates)) and validates the result — the generic fallback for a backend with no on-the-fly flattener and the oracle the fast path is checked against. The intended fast path (a multi-pass backend, per docs/composition.md currently only emp-ag2pc's run_compose) replays each instance's gate stream on the fly and never materializes the flattened program; no in-tree emp-tool backend consumes plans yet.
  • Caller obligations. Units should be WireReuse::Linear for a multi-pass-backend lowering (frontend/compose.h:12) — ComposeCtx does not check this structurally beyond validate_program's generic reuse checks. Nested / multi-level composition is not yet supported: a unit whose body itself called run(ctx, subunit) had the subunit inlined at compile time (docs/composition.md:120-131).
Hierarchy + function equality tested

test_compose.cpp:43-80 checks two shapes — a 3-call chain and a 2-call SIMD+glue body: the plan records exactly N instances (plan.events.size() == 3 for the chain, i.e. O(#instances), not flattened gates), and flatten_compose(plan) computes the identical function to compiling the same body with ordinary compile() (which inlines) over random inputs.

Non-owning unit references

A ComposeInstance holds a raw const BooleanProgram* (compose.h:29): a ComposePlan is only valid while every referenced unit outlives it. Nothing pins or copies the unit — a plan that outlives its Circuit objects dangles. An auditor of a consuming backend should confirm unit lifetime is anchored for the plan's whole replay window.

B.3 · Cross-context checks & the digest duality

ir/context/checks.h ir/context/digest.h

Cross-context checks are debug-only by default

checks.h's check_same_context(l,r) (checks.h:23-34) verifies both operands' context pointers are non-null and equal. The default policy is DEBUG-ONLY (EMP_CONTEXT_CHECKS defaults to 1 only when NDEBUG is unset, checks.h:15-21); opt in to always-on with -DEMP_CONTEXT_CHECKS=1 (which raises error(), not just assert, so it survives NDEBUG once opted in), or force off with -DEMP_CONTEXT_CHECKS=0. In a Release build with no opt-in, mixing typed values from two different contexts is unchecked — most dangerous for id-based wires (two RecordCtxes both start ids at 0 and silently alias).

Digest encoder duality

DigestCtx and the standalone digest_program (digest.h:59-78) map ops to integers independently (the gate stream is hashed as And=0…Const1=4 in a defaultless switch at digest.h:67-74, with the same const-dedup and the same external_input(num_inputs) prefix mix at digest.h:62) — they MUST stay in sync (the header comment flags this at digest.h:4-9). Divergence would silently break determinism/staleness checks. digest_source (digest.h:84-92) streams a body through a DigestCtx and equals digest_program of the program the body records — the basis for the frontend's "recording is deterministic" test (test/circuits/test_circuit_fn.cpp). The digest is also the staleness guard on cached schedules (§A.5).

C · The generic WireValue concept

ir/wire_value.h

WireValue is the generic structural contract for a typed value object over a BooleanContext: a fixed-width bundle of wires with a clear-value codec, packable to / constructible from raw Ctx::Wire, rebindable to another context, and reporting its own context pointer. It is the context-free vocabulary the IR execution and session layers speak; it names no concrete value family (Bit/UInt/Int/Float/BitVec) and no protocol (wire_value.h:4-31). The contract is split into a structural WireBundle and the codec-adding WireValue (wire_value.h):

template <class V_>
concept WireBundle =                                                    // what EXECUTION needs (no codec)
    requires { typename V::Wire; typename V::context_type; } &&
    BooleanContext<typename V::context_type> &&                         // a real gate context
    std::same_as<typename V::Wire, typename V::context_type::Wire> &&    // its wire IS that context's wire
    requires { typename std::integral_constant<int, V::width()>; } &&   // static, compile-time width
    std::same_as<typename V::rebind<V::context_type>, V> &&             // identity rebind
    requires(const V v, V::Wire* out)            { v.context(); v.pack_wires(out); } &&
    requires(V::context_type& c, const V::Wire* in){ { V::from_wires(c, in) } -> std::same_as<V>; };

template <class V_>
concept WireValue = WireBundle<V_> &&                                   // + the clear-value codec
    requires { typename V::clear_t; } &&
    requires(V::clear_t cv, const bool* bits)    { { V::encode(cv) } -> std::same_as<std::array<bool, V::width()>>;
                                                   { V::decode(bits) } -> std::same_as<V::clear_t>; };

Two requirements distinguish it from a looser "has wires" check:

  • It binds to a real gate context. BooleanContext<context_type> and Wire == context_type::Wire are both required (in WireBundle, wire_value.h) — a value cannot claim a wire type its context does not use.
  • It is fixed-width only. width() must be usable as a compile-time std::integral_constant<int, …> template argument (in WireBundle, wire_value.h), so a runtime-width value (whose width() is requires (N>0) and absent at N==0) models neither WireBundle nor WireValue and is never compiled. It instead models a separate RuntimeWidthValue concept (wire_value.h), so it is session-I/O eligible through the runtime-width input/reveal overloads — only the frontend boundary excludes it.

Every requirement is spelled through std::decay_t<V_> so the concept is stable under reference qualification. A convenience is_wire_value_v<V> variable template (wire_value.h:77) gives the boolean form. The frontend keeps a stricter RecordValue concept (circuit_fn.h) that refines WireBundle by additionally requiring context_type == RecordCtx (no clear codec is needed) — see Report 3.

D.1 · The session layer & the reveal contract

ir/session/session.h ir/session/session_io.h

The gate concept has no I/O; the session concept is its peer and owns the I/O boundary. The session layer is a small family of concepts, not one monolith — a session names no circuit value family, because values are context-bound (UInt_T<ctx_t,N> etc.), so adding a value family needs no session edit (session.h:4-18).

// ir/session/session.h
template <class S> concept Session =                         // the minimal protocol object
    requires(const S& s) { { s.party() } -> std::convertible_to<int>; };

template <class S> concept DirectSession =                   // + a direct/user gate context
    Session<S> && requires(S& s) {
        typename S::ctx_t;
        requires BooleanContext<typename S::ctx_t>;
        { s.ctx() } -> std::same_as<typename S::ctx_t&>;
    };

template <class S> concept CheckpointingSession =            // + a checkpoint() barrier
    Session<S> && requires(S& s) { s.checkpoint(); };
  • Session (session.h:36-38) is the floor: it reports a party() convertible to int. Nothing else is mandatory.
  • DirectSession (session.h) adds a ctx_t type (itself a BooleanContext) reachable via ctx() — the gate context operator-mode circuits are built over. A multipass protocol may own many internal pass contexts; ctx_t is only the direct one.
  • CheckpointingSession (session.h:49-52) is an optional refinement for sessions carrying cross-call materialized state (direct / multi-pass protocols where wire labels must survive across invocations); it adds a checkpoint() barrier. A stateless session (e.g. ClearSession) has no such barrier and does not model this concept.

A spelling helper ctx_t<S> = S::ctx_t (session.h) lets tests/docs name a session's direct context without a session value alias.

The reveal contract is a separate, generic concept SessionIO<S,V> (session_io.h), parameterized over any WireValue V whose context_type is S::ctx_t:

// ir/session/session_io.h — recipient-explicit, uniform over any WireValue
S::reveal_t<V> == std::optional<typename V::clear_t>   // required equality
s.input<V>(party, x) -> V                              // feed a clear value as `party`'s input
s.reveal(v, party)   -> std::optional<clear_t>         // present only on a party that learns it

Because SessionIO is generic over WireValue, a session names no value family — adding a value family needs no session edit (session_io.h:4-9). The revealed value is present only on a party that learns it (every party for PUBLIC, the named recipient otherwise) and std::nullopt elsewhere.

Why the session names no value family

Responsibilities are split so a session is value-family-agnostic: Session requires only party(); the gate context is named once as DirectSession::ctx_t; and I/O is the orthogonal, value-generic SessionIO<S,V> over any WireValue. A new value family is usable through any session with no session edit, and CheckpointingSession is an opt-in refinement rather than part of the base contract.

D.2 · ClearSession — the plaintext reference

ir/session/clear_session.h

ClearSession (clear_session.h) is the trivial realization of the session contracts. It owns a pure ClearCtx and declares ctx_t == ClearCtx (clear_session.h). Since there are no secrets in the clear, input becomes public wires and reveal reads wire values back into an always-populated optional.

  • ctx() returns ctx_t& (clear_session.h) — the gate context for value construction that is not I/O (public constants, crypto kernels).
  • party() reports PUBLIC (clear_session.h:49) — plaintext has no private party, so PUBLIC is the universal-knowledge convention.
  • reveal_t<V> is std::optional<typename V::clear_t> (clear_session.h:46); ClearSession always knows the value, so its optional is always populated, for every recipient.

Owner / recipient validation. input(owner, value) and reveal(value, recipient) accept and then ignore the party for routing (correct for plaintext — there are no secrets) — but only after validating it is a real party id: both error() only when the party id is below PUBLIC (the XOR=-1 share sentinel), so any PUBLIC or party id ≥ 1 is accepted — the plaintext oracle serves n-party protocols too (clear_session.h; the enum is {XOR=-1, PUBLIC=0, ALICE=1, BOB=2} in runtime/core/constants.h). So ClearSession ignores routing but does not silently accept the share sentinel — a real protocol session (SH2PC / AG2PC) would additionally route by the id, and an auditor should confirm those do not ignore it.

Codec-width check is always-on

input encodes through V::encode(value) into a std::array<bool, V::width()> whose size is fixed by the type, so a codec emitting the wrong bit count is a compile-time error (clear_session.h) — stronger than always-on, and impossible to out-of-bounds the wire fill that follows. A static_assert additionally pins V::context_type == ctx_t at both input and reveal (clear_session.h). The bottom of the file static_asserts Session<ClearSession> and DirectSession<ClearSession> (clear_session.h); SessionIO<ClearSession,V> for a concrete value type is asserted in the emp-tool tests, since naming a value family in the header would make ir depend on circuits/.
